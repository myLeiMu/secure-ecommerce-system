## 探测环境与范围

`scripts/week7_dast.py` 以真实 HTTP 请求访问本机 WSGI，只连接随机 localhost 端口；账号、订单、银行卡样例均来自内存 SQLite，每次结束销毁。脚本仅执行有限探测。2026-10-07 用户补充了 Burp 原生 HTML 报告，目标为 HTTP 3000；提交副本移除了 JWT 及正文。该报告不证明完整扫描三个角色，也未覆盖 HTTPS 8443。统计、人工研判和限流影响见 [Burp 分析](reports/DAST-分析.md)，操作见 [课堂演示](第7周手动演示.md)。

覆盖口径：SQLi 样例在商品查询被拒绝 400；XSS 样例得到 JSON 且未反射原始 `<script>`；无令牌跨站管理写入 401；交易用户 B 请求交易用户 A 的订单 403；登出前个人资料 200、登出后 401，伪造令牌 401；资料接口完整卡号基线为 true、修复后 false。单个输入样例并不能证明所有 SQLi/XSS/CSRF 路径安全。API 使用 Bearer 请求头而不依赖浏览器自动附带的会话 cookie，因而该无令牌跨站写入检查与 Django 表单 CSRF 不是同一攻击模型。响应已有 `nosniff` 和 `DENY`，目前没有 CSP；静态前端若由 nginx 服务，仍需单独检查网关响应头。

Bandit 的 B413 对 `Crypto.Cipher._mode_gcm` 报“PyCrypto 已弃用”；实际安装是 PyCryptodome 3.21.0，属于维护中的分支，因此库弃用结论不成立。但代码调用的是私有 API，升级仍有兼容风险，保留为技术债并用 RFC 8998 向量/跨语言测试守护。B305 所指 ECB 仅用于 GCM 引擎计算块加密原语，业务数据必须经过 GCM 标签验证；这不是裸 ECB 数据加密。四条 B311 位于当前运行 API 未调用的教学 RSA 实现，若未来接入正式密钥生成，必须先换成 CSPRNG 并提高密钥长度。B105 是 Swagger 文档中的省略号 JWT 示例，不是有效密钥。

## 修复、验证与遗留边界

本次修复的四类问题及证据对照见 [漏洞清单](第7周漏洞清单.md)。前端依赖在既有版本约束内执行 `npm audit fix`，随后执行生产构建、23 项 Jest 测试。后端 [20 项隔离安全测试](evidence/week7/backend-regression.txt) 通过，新增断言覆盖登录/个人资料/银行卡绑定接口不返回完整卡号；隔离 DAST 修复前后结果可比较。`git diff --check` 无空白错误。没有伪造个人提交或第三方扫描截图。

待处理的阻断项：Python 运行依赖升级及回归、构建链 2 条 high 无可用自动修复、代码中仍有演示支付商户私钥默认值。Django 部署检查剩下 HSTS 和 HTTPS 重定向两条网关相关提醒；本机也支持 3000 开发入口，不能直接在 Django 层打开强制跳转或 HSTS，需要核对 nginx 正式入口和域名后配置。责任人与完成顺序写在 [漏洞清单](第7周漏洞清单.md)；这些问题在处理前不能声明整站安全验收通过。

## 复现命令

在项目根目录进入 WAF 环境。Bandit 1.9.4 和 pip-audit 2.10.1 已直接安装在 WAF；首次配置其他机器时，可先运行下方安装命令。扫描器是开发/审计工具，不需要放进应用运行依赖文件：

```powershell
conda activate WAF
python -m pip install bandit==1.9.4 pip-audit==2.10.1
python -m bandit -r api_service/api src -f json -o docs/evidence/week7/bandit-rerun.json -x src/tests,src/example_usage.py
python -m pip_audit -r docs/requirements/requirements.txt --no-deps --disable-pip -f json -o docs/evidence/week7/pip-audit-rerun.json
python scripts/week7_dast.py --label regression
python scripts/week7_config_check.py --label regression
python scripts/week7_secret_check.py
cd frontend
npm audit --json
npm audit --omit=dev --json
npm test -- --runInBand
npm run build
```

Bandit、pip-audit、npm audit 发现问题时可能以非零状态退出，应先阅读生成的报告，不把非零退出码一律当成扫描失败。对工具输出的风险判断须结合可达性和受影响环境。依赖风险报告随漏洞数据库变化，不应期待重新运行后数字永远相同。

依据：[Bandit 命令文档](https://bandit.readthedocs.io/en/latest/man/bandit.html)、[pip-audit 官方说明](https://github.com/pypa/pip-audit)、[Django 部署清单](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/)、[PyCryptodome GCM 文档](https://pycryptodome.readthedocs.io/en/latest/src/cipher/modern.html)。
