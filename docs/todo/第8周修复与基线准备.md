## 2. 代码怎么改、为什么改

1. `src/algorithm/RSA.py`、`rsa_core.py`：将教学 RSA 的 `random` 换为 `secrets.randbelow/randbits`，默认每个素数 1024 位。修复可预测随机数来源；不把教学裸 RSA 声称为可直接用于生产的完整加密协议。
2. `src/crypto_tunnel.py`：升级后确认原生 SM4-GCM 可用，改用 cryptography 公共 Cipher/GCM API，去掉 PyCryptodome 私有 `_mode_gcm` 和内部 ECB 适配。固定 16 字节标签，验证失败抛错，不返回未认证明文；没有弱算法降级。原协议字段、AAD、SM2 封装和重放校验不变。
3. `frontend/vue.config.js`：开发服务器仅监听 127.0.0.1，限制 allowedHosts，并加 X-Frame-Options、CSP frame-ancestors、nosniff、Referrer-Policy。支持的页面、图片 URL 功能不变；本次 CSP 只约束嵌入、对象与 base，并非完整脚本源白名单策略。
4. `scripts/prepare_wsl_mtls.py` 和 `harden_wsl_nginx.py`：模板与本机实际 nginx 都加安全响应头并清空外部转发 Host。配置先备份、`nginx -t` 再 reload，校验失败会恢复文件。顺带修复 `/products` 与静态图片目录重名时 301/403 的 SPA 路由问题。
5. 电商/银行 settings：移除商户密钥兜底；本机 `.env` 配对轮换，备份仅放忽略的 `keys/payment-backups`。3 个电商支付入口缺钥返回 503。银行 6 项测试改为每次生成临时测试密钥，使用独立 SQLite 测试库。
6. 第 2、4、7 周证据脚本新增 `--output-dir`，使本轮证据单独归档，不覆盖历史原件。

原 Bandit 的 B413/B305 是对适配层的人工研判项，不等同于已确认可利用漏洞；本轮通过删除私有适配实现消除相关技术债。剩余 B105 是不完整文档示例，不是有效 JWT，没有通过 `nosec` 或缩小扫描范围掩盖它。

## 4. 压测准备与初始基线

三个任务接口：`POST /api/auth/login`、`GET /api/products`、`POST /api/orders`。下单前用 `POST /api/cart` 加入一件测试商品；购物车准备请求独立统计。

交付 [JMeter 脚本](../../performance/week8-baseline.jmx)、[环境/指标说明](../../performance/README.md)、[执行器](../../scripts/week8_perf.py)。最终结果在 [performance-final](../evidence/week8/performance-final/results.json)，可直接阅读 [三轮统计与监控表](../evidence/week8/performance-final/summary.md)，环境与代码指纹在 [environment.json](../evidence/week8/performance-final/environment.json)。

固定 1 用户、1000 件库存为 1 的二手测试商品，每请求前等待 1 秒；1 次冒烟，3 轮各 2 次预热＋10 次测量。保留真实密码计算、JWT、权限、审计和限流，验证下单落库。输出逐请求 JTL、p95/吞吐/错误率、CPU/RSS 采样。原始正文和 JWT 不进入采样文件。

三轮最终结果：登录 p95 为 3194/2944/2992ms，商品查询为 9/10/9ms，下单为 13/14/16ms；三个目标接口均为 0% 错误率。每轮 12 张新测试订单（含 2 张预热订单）落库，购物车清空。登录较慢是后续 profiling 的线索，尚未证明具体瓶颈位置。

这是隔离 SQLite、单进程 wsgiref 的**低负载联通基线**，不是 WSL nginx/MySQL 的容量成绩。10 样本的 p95 等于最大值，不能据此证明第 9 周性能达标。第 9 周须选择并固定正式压测环境，延长采样、分配独立交易账号/商品，再优化和复测；不能跨环境比较。

首轮 JMeter 的购物车前置路径错写 `/api/cart/items`，导致 404，未计为成功；[失败 JTL](../evidence/week8/performance/smoke.jtl) 保留。修正路径后通过三轮联通验证；考虑到当时有回归/扫描同时运行，这些记录放 `performance-verified` 作调试参考，正式初始数据另跑到 `performance-final`，避免混用。

## 5. 尚未闭环的项目与验收边界

1. **前端构建依赖仍有 49 条告警（14 high）**。npm 报多个路径无可用修复，包括 Vue CLI、webpack-dev-server/middleware、postcss、serialize-javascript 等。本轮做相容修复，未用 `--force` 安装不相容大版本；生产依赖 0 不代表开发机/CI 无风险。当前措施是回环监听、只构建可信项目输入；这属于降低暴露面，不能标成漏洞已修复。后续需评估替换 Vue CLI 或跟进上游补丁，并重新运行 npm audit、前端测试、构建和页面检查。是否接受暂缓风险须由小组/教师确认。
2. **Burp Professional 修复后同范围复扫仍需人工操作**。本轮有限 HTTP 探测与 nginx 响应头检查不能冒充 Burp 扫描报告。保留第 7 周 [Burp 原报告脱敏副本](../reports/DAST-脱敏.html)。操作步骤见下一节。
3. **真实 8443 API 链路待服务重启后复验**：检查时 nginx 页面正常，但 Windows 8080 未监听，`/api/health/` 超时。银行 8000 当时仍是已有进程。支付密钥和 Python 依赖更新后，必须先结束正在演示的支付，再重启电商/银行两端；没有为了测试强杀现有银行进程。
4. HTTPS 网关的 HSTS/HTTP 跳转策略仍需按正式域名决定；开发 HTTP 3000 的“明文传输”发现不会因增加防嵌入头消失。生产验收使用 HTTPS，不能删除 HTTP 开发报告来宣称解决。
5. 银行卡仅响应脱敏，数据库加密尚未实现；源码历史中的演示私钥已轮换失效，Git 历史未重写。扫描的 0 条仅针对工具和范围，不是“整站无漏洞”的证明。

因此，本周有可评审的修复、扫描、回归与初始性能证据；**在 Burp 复扫、真实入口复验和构建链风险处置尚未完成前，不应勾选“全部漏洞闭环”。**

## 6. 课堂前补齐的手动操作

先结束当前支付演示，关闭原有银行服务窗口；分别在两个终端启动：

```powershell
conda activate WAF
python api_service/manage.py runserver 0.0.0.0:8080 --noreload
```

```powershell
conda activate WAF
python bank_service/manage.py runserver 0.0.0.0:8000 --noreload
```

两条命令都在项目根目录运行。不要再运行密钥轮换脚本；本机这次已经配对更新。`keys/payment-backups` 仅用于排障，不提交、不把已泄露旧密钥恢复为正式密钥。

浏览器先打开 `https://localhost:8443/api/health/`，确认 JSON 且服务状态正常；再用 week1_buyer 的证书登录，确认只允许自身资源。分别用 week1_admin/week1_auditor 证书登录，确认必须完成 TOTP，审计员不能管理用户；重新做一次正确请求/重放/篡改的第 4 周演示，保留脱敏抓包。

Burp 步骤：

1. 代理仅保留 `127.0.0.1:8081`，关闭 8080 监听，避免占用后端。Intercept off，浏览器只代理本机教学系统。
2. 如果要与第 7 周 HTTP 3000 原报告逐项对比，另启 `npm run dev`，先复扫同一 HTTP 范围；再单独扫描 HTTPS 8443，两个范围分开记录。
3. HTTPS 需要浏览器信任 Burp CA；证书登录时在 Burp 的 TLS Client Certificates 配置匹配账号的 P12。一个账号一轮，不假定 Burp 会按网页用户名自动切换证书。
4. 先手动登录并浏览对应角色页面，确认 History 返回业务 JSON，而非 401/429/登录页；用有效请求执行 Scan → Audit selected items，保存任务范围与配置。降低并发、增加请求间隔；遇到 429 保留记录并降速重测。
5. 对比前端 HTML 的 DENY/CSP、异常 Host 拒绝/忽略、恶意 Origin 无 CORS 放行头、越权拒绝和脱敏响应。信息级提示逐项研判，不把“反射输入”“200 响应”直接认定为 XSS/CORS 漏洞。
6. 导出修复后 HTML 报告和任务摘要：入口、时间、角色、工具版本、配置、成功认证证据、状态码分布。原件留本机，删除 token/cookie/个人数据后提交；不要把原始含凭据请求写进 Git。
