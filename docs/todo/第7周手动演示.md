## 本机隔离复跑

在根目录运行 `conda activate WAF` 后执行：

```powershell
python scripts/week7_dast.py --label regression
```

## Burp Suite / HackBar 现场补充

1. 用三个 `week1_` 课堂账号启动既有后端、前端与 WSL nginx。Burp 代理浏览器访问 `https://localhost:8443`；按既有证书演示文档导入 Burp CA 与客户端 P12。也可在 `http://localhost:3000` 用密码和必要的 TOTP 登录，避免改动 nginx。把目标范围限定本机和课堂测试账号。
2. 用交易用户 A 打开“我的订单”，在 Burp Repeater 保存 `GET /api/orders/<A 的订单号>`。把 Authorization 换成另一名交易用户 B 的有效 JWT，预期 403/404；原账号请求预期 200。不要把 JWT 放入提交报告。
3. 直接访问 `GET /api/products?keyword=%27%20OR%201%3D1--`，预期 400；再使用 `<script>alert(1)</script>` 作为 keyword，查看响应是 JSON 且脚本原样未出现在正文。它们是有限样例，不能把结果说成“全站不存在 SQLi/XSS”。
4. 在 Repeater 去掉 Authorization 并加 `Origin: https://evil.invalid`，对 `/api/admin/categories` 提交虚构分类，预期 401，且无允许该来源的 CORS 头。JWT 由 JS 明确放请求头，这个检查主要验证无认证写入不会成功。
5. 测会话：用 A 的有效 JWT 请求 `/api/users/profile` 得 200，登出后原样重放得到 401。资料响应 `bank_card_number` 仅为掩码；课堂不要使用真实银行卡号。
6. 保存 Burp 报告时，去掉 JWT、Cookie、动态码、完整卡号和私人地址。2026-10-07 已补充 [Burp 脱敏报告](reports/DAST-脱敏.html) 与 [逐项分析](reports/DAST-分析.md)；原始 `docs/reports/DAST.html` 含凭据，仅本机保留，不应共享提交。

现有 `api_service/tests/week7_8_acceptance_demo.py` 会清空购物车并创建商品/订单；只在隔离测试账号与测试环境运行。它现在从 `WEEK7_TOKEN_A/B` 读取令牌，已不在源码内硬编码。Burp 单次演示比该脚本更适合课堂展示；不要在真实账号上运行这份有写操作的演示脚本。
